# CKA — Certified Kubernetes Administrator (Exam Guide & Mastery)

The Certified Kubernetes Administrator (CKA) certification is a 100% performance-based exam conducted in a remote Linux command-line environment. It tests your ability to architect, install, configure, manage, network, secure, and troubleshoot production Kubernetes clusters.

- **Exam Duration**: 120 minutes (2 hours)
- **Format**: ~15–20 hands-on performance tasks on multi-node clusters
- **Passing Score**: 66%
- **Allowed Resources**: Official docs (`kubernetes.io/docs`, `kubernetes.io/blog`, `github.com/kubernetes`, `helm.sh/docs`). Single browser tab in proctored UI.

## 🛠️ Domain 1: Troubleshooting (30%)

Troubleshooting is the single highest-weighted section. Speed and systematic isolation are critical.

### 1.1 Node Failure Diagnosis (`NotReady` State)
When a node reports `NotReady`, execute this exact diagnostic ladder:

```bash
# 1. Identify which node is NotReady and inspect node conditions
kubectl get nodes -o wide
kubectl describe node <failing-node> | grep -A 10 Conditions:

# 2. SSH into the troubled node
ssh <failing-node>

# 3. Check kubelet service status and journal logs
sudo systemctl status kubelet
sudo journalctl -u kubelet -n 100 --no-pager

# 4. Check container runtime (containerd or CRI-O)
sudo systemctl status containerd
sudo journalctl -u containerd -n 50 --no-pager

# 5. Common causes & solutions:
# Cause A: Swap enabled (kubelet fails by default if swap is on)
sudo swapoff -a

# Cause B: Kubelet config path error or cert mismatch
ls -la /var/lib/kubelet/pki/
cat /var/lib/kubelet/config.yaml

# Cause C: Container runtime socket dead or path mismatch
sudo systemctl restart containerd
sudo systemctl restart kubelet
```

### 1.2 Control Plane Static Pod Troubleshooting
Static pods (`kube-apiserver`, `kube-controller-manager`, `kube-scheduler`, `etcd`) are defined under `/etc/kubernetes/manifests/`.

- If the API Server is down, `kubectl` will return `The connection to the server <ip>:6443 was refused`.
- In this state, use `crictl` directly on the control plane node:

```bash
# Set crictl endpoint if not configured
sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock ps -a

# Check logs of stopped or erroring control plane pods
sudo crictl logs <container-id>

# Inspect static pod manifests for syntax errors or bad flags
ls -la /etc/kubernetes/manifests/
cat /etc/kubernetes/manifests/kube-apiserver.yaml
```

### 1.3 Application & Pod Crash Troubleshooting
- **CrashLoopBackOff**: Application error inside container, missing env var, failed command, or port conflict.
  ```bash
  kubectl logs <pod-name> --previous
  kubectl describe pod <pod-name>
  ```
- **ImagePullBackOff / ErrImagePull**: Typo in image name, non-existent tag, or missing imagePullSecret.
- **Pending**: Node scheduling issue (taints, lack of CPU/Memory, unsatisfied nodeAffinity/nodeSelector, PVC unbound).
  ```bash
  kubectl describe pod <pod-name> | grep -A 5 Events:
  ```

## 🏗️ Domain 2: Cluster Architecture, Installation & Config (25%)

### 2.1 Cluster Bootstrap with `kubeadm`
```bash
# Initialize control plane
sudo kubeadm init --pod-network-cidr=192.168.0.0/16 --kubernetes-version=v1.31.0

# Setup kubeconfig for regular user
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# Install CNI (e.g. Flannel or Calico)
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/calico.yaml

# Join worker nodes (token command generated by init)
sudo kubeadm join <control-plane-host>:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash>

# Generate new token if expired:
sudo kubeadm token create --print-join-command
```

### 2.2 In-Place Cluster Upgrade Procedure
> [!IMPORTANT]
> Never skip minor versions (e.g. 1.30 -> 1.31 -> 1.32). Always upgrade first control plane first, then others, then worker nodes.

#### Upgrading Control Plane Node:
```bash
# 1. Unhold & install kubeadm target version
sudo apt-mark unhold kubeadm
sudo apt-get update && sudo apt-get install -y --allow-change-held-packages kubeadm=1.31.1-1.1
sudo apt-mark hold kubeadm

# 2. Plan and apply upgrade
sudo kubeadm upgrade plan
sudo kubeadm upgrade apply v1.31.1 -y

# 3. Drain control plane node
kubectl drain <cp-node-name> --ignore-daemonsets --delete-emptydir-data

# 4. Upgrade kubelet and kubectl
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y --allow-change-held-packages kubelet=1.31.1-1.1 kubectl=1.31.1-1.1
sudo apt-mark hold kubelet kubectl

sudo systemctl daemon-reload
sudo systemctl restart kubelet

# 5. Uncordon node
kubectl uncordon <cp-node-name>
```

#### Upgrading Worker Nodes:
```bash
# 1. Drain worker from control plane
kubectl drain <worker-node> --ignore-daemonsets --delete-emptydir-data

# 2. SSH into worker & upgrade kubeadm
sudo apt-mark unhold kubeadm
sudo apt-get update && sudo apt-get install -y --allow-change-held-packages kubeadm=1.31.1-1.1
sudo apt-mark hold kubeadm

# 3. Upgrade node config
sudo kubeadm upgrade node

# 4. Upgrade kubelet and kubectl
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y --allow-change-held-packages kubelet=1.31.1-1.1 kubectl=1.31.1-1.1
sudo apt-mark hold kubelet kubectl
sudo systemctl daemon-reload && sudo systemctl restart kubelet

# 5. Uncordon worker from control plane
kubectl uncordon <worker-node>
```

### 2.3 etcd Snapshot Backup and Restore
```bash
# Parameters needed from /etc/kubernetes/manifests/etcd.yaml:
# --cacert=/etc/kubernetes/pki/etcd/ca.crt
# --cert=/etc/kubernetes/pki/etcd/server.crt
# --key=/etc/kubernetes/pki/etcd/server.key
# --endpoints=https://127.0.0.1:2379

# BACKUP
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/etcd-backup.db

# VERIFY
ETCDCTL_API=3 etcdctl --write-out=table snapshot status /opt/etcd-backup.db

# RESTORE TO SEPARATE DIRECTORY
ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-restored

# Update static pod /etc/kubernetes/manifests/etcd.yaml:
# Change hostPath volume for etcd-data from /var/lib/etcd to /var/lib/etcd-restored
```

### 2.4 Role-Based Access Control (RBAC)
Imperative generators save huge time:
```bash
# Create Role
kubectl create role pod-reader --verb=get,list,watch --resource=pods,pods/log -n dev

# Bind to User
kubectl create rolebinding pod-reader-binding --role=pod-reader --user=developer-dave -n dev

# Bind to ServiceAccount
kubectl create rolebinding sa-reader-binding --role=pod-reader --serviceaccount=dev:app-sa -n dev

# ClusterRole & ClusterRoleBinding
kubectl create clusterrole deployment-manager --verb=create,get,list,watch,update,delete --resource=deployments
kubectl create clusterrolebinding dep-mgr-binding --clusterrole=deployment-manager --group=dev-leads

# Test permissions with can-i
kubectl auth can-i create deployments --as=developer-dave -n dev
kubectl auth can-i delete pods --as=system:serviceaccount:dev:app-sa -n dev
```

## 🌐 Domain 3: Services & Networking (20%)

### 3.1 Service Types and Port Mapping
- `port`: Port that the Kubernetes Service listens on inside the cluster.
- `targetPort`: Port that the container/application listens on in the Pod.
- `nodePort`: Port on each cluster node's IP (range 30000–32767).

```bash
# Create ClusterIP service
kubectl expose deployment frontend --name=frontend-svc --port=80 --target-port=8080

# Create NodePort service
kubectl create service nodeport web-svc --tcp=80:80 --node-port=31080
```

### 3.2 Ingress Routing
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - host: myapp.example.com
    http:
      paths:
      - path: /billing
        pathType: Prefix
        backend:
          service:
            name: billing-svc
            port:
              number: 8080
```

### 3.3 CoreDNS Resolution Architecture
- Standard Pod FQDN: `<pod-ip-dashed>.<namespace>.pod.cluster.local`
- Standard Service FQDN: `<svc-name>.<namespace>.svc.cluster.local`
- Test cluster DNS from interactive pod:
  ```bash
  kubectl run dns-test --image=busybox:1.28 --rm -it --restart=Never -- nslookup billing-svc.default.svc.cluster.local
  ```

### 3.4 NetworkPolicies
Default deny ingress + allow specific source:
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-allow-web
  namespace: prod
spec:
  podSelector:
    matchLabels:
      role: api
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          role: frontend
    ports:
    - protocol: TCP
      port: 8080
```

## 📦 Domain 4: Workloads & Scheduling (15%)

### 4.1 Imperative Workload Commands
```bash
# Create deployment
kubectl create deployment my-deploy --image=nginx:1.26 --replicas=3

# Scale
kubectl scale deployment my-deploy --replicas=5

# Rolling update & history
kubectl set image deployment/my-deploy nginx=nginx:1.27 --record
kubectl rollout status deployment/my-deploy
kubectl rollout history deployment/my-deploy
kubectl rollout undo deployment/my-deploy --to-revision=1
```

### 4.2 Pod Scheduling Controls
1. **nodeSelector**: Simple key-value matching
   ```yaml
   spec:
     nodeSelector:
       disktype: ssd
   ```
2. **nodeAffinity**: Rich expressive rules (requiredDuringSchedulingIgnoredDuringExecution vs preferred)
3. **Taints & Tolerations**: Keep pods away from nodes unless tolerated
   ```bash
   # Add taint to node
   kubectl taint nodes node1 dedicated=special:NoSchedule

   # Pod toleration to allow placement on node1:
   # tolerations:
   # - key: "dedicated"
   #   operator: "Equal"
   #   value: "special"
   #   effect: "NoSchedule"

   # Remove taint (note the minus suffix)
   kubectl taint nodes node1 dedicated=special:NoSchedule-
   ```

## ⚡ Speed & Time-Management Cheatsheet for CKA

1. Set up your `.bashrc` in the first 30 seconds (`alias k=kubectl`, `export do="--dry-run=client -o yaml"`).
2. Generate base YAML files using `$do`:
   ```bash
   k run nginx-pod --image=nginx $do > pod.yaml
   k create deployment webapp --image=nginx:alpine --replicas=3 $do > dep.yaml
   ```
3. Use `kubectl explain --recursive <resource>.<field>` to find fields instead of scrolling documentation.
4. Always verify you are on the instructed cluster context (`kubectl config use-context <name>`).
5. Double-check namespace for every single question.
